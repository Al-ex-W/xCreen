# Native/runtime receipt contract

RPC request keys use snake_case. All responses are bounded before gateway stdout.

- `xcreen.batch.context {session_id,mode:"manual"}`: **mandatory before every manual prompt**, while the native FIFO owns an idle session. Revokes any automatic context. Manual writing, if explicitly enabled by this context, uses a separate `xcreen_manual_daily_note` tool and cannot supply batch/day identity. `xcreen.batch.context` with the prepare shape is equivalent to prepare. Contexts are process-memory only, per runtime session and pinned to the first host-injected tool turn ID; a different turn cannot reuse them. If an automatic turn produces no tools, native must still revoke its context before the next turn. Never expose these RPCs as model tools.
- `xcreen.batch.prepare {session_id,batch_id,source_ids:[String]}`: host validates exact IDs against the persisted native batch, freezes its immutable source binding, binds the active session, and returns `{batch_id,source_ids,session_id,prepared:true}`. Idempotent for the exact binding; conflicts fail. The session binding may move to a new runtime session only while the batch has no effect rows and no terminal result (native-authorized retry); re-preparing an effect-free batch also clears a stale turn pin left by a failed turn. Once any effect exists the binding and pin are immutable. This runs only while that automatic turn exclusively owns the native queue, before prompt submission. The native send intent is persisted first, so a crash never permits blind resend.
- `xcreen.batch.receipt {session_id,batch_id,source_ids:[String],reconcile:true}`: read-only note verification; never appends/repairs notes. IMPORTANT: `session_id` here is the original persisted preparation identity, which may no longer be a live gateway runtime after cold resume. Receipt lookup must validate it against the durable batch row without requiring `_sess_nowait` to find that old live session; otherwise startup recovery cannot work. Host returns `{batch_id,source_ids,session_id,status,verified,effects:[...]}`. `status` is `saved`, `skipped`, `missing`, or `uncertain`. A non-terminal prepared batch additionally carries strict boolean `retry_safe`: `true` only when the ledger holds **zero** effect rows for that batch (reserved, pending, completed or uncertain — including unledgered conflicting markers, which are now bound to the batch) and no terminal result. Terminal and missing receipts never carry `retry_safe:true`; old hosts omit it, which native treats as not retry-safe. Saved requires nonempty exact effect receipts whose note blocks are read-back verified; skipped requires explicit persisted model result with zero effects. Only verified saved/skipped completes native processing. Missing/uncertain is not success. Native matches every binding field and retains the bounded response.
- Model tool `xcreen_batch_result`: `{outcome:"saved",effect_ids:[ENTRY_ID,...]}` or `{outcome:"skipped",reason:"no_useful_fact",effect_ids:[]}`. Host validates immutable prepared binding and persists explicit saved (exact effect identities) or skipped (zero effects) result. Returns the same bounded terminal receipt shape as receipt lookup, only after commit/readback. Assistant prose, terminal messages and compactable history are never receipt authority.
- Model writer `xcreen_daily_note`: `{entry_id:STABLE_SEMANTIC_ID,fact:TEXT,source_ids:[ID,...]}`. Automatic-only; no `batch_id`, paths or caller day allowed. Returns `{written,day,entry_id,source_ids}` (an exact retry can instead return `reason:"already_recorded"`). The separate `xcreen_manual_daily_note` has the same arguments but requires explicit host manual context and never produces automatic batch effects.
- `xcreen.batch.reconcile` is an alias of the receipt operation, with the same original-session/source binding and response shape.
- `xcreen.history.page {session_id,cursor?:String,max_bytes:48000,limit:20}`: host sanitizes pixels and byte-bounds the complete encoded result before stdout. Returns `{messages:[...],next_cursor:String|null,...}`. Opaque stable snapshot cursors survive concurrent reads; stale/evicted cursors fail explicitly. Oversized messages are placeholders; never call full `session.history` first.

Native metadata survives raw evidence expiry, strips raw OCR/images on expiry, retains exact source IDs and receipts, and uses a bounded archive. Startup reconciliation and explicit `xcreen verify` query exact persisted batches, not history; neither starts inference nor rewrites notes. Verification may update native metadata only.

## Runtime registration and launch

The bundled launcher starts the real installed gateway with `--hermes-root ROOT --evidence-root ROOT [--vault ROOT] [--timezone Europe/Stockholm]`. It calls the installed public `tools.registry.registry.register` and `tui_gateway.server.register_method(name, handler)` seams, then the unmodified `tui_gateway.entry.main`. No stock handler is replaced, no profile/plugin file is edited, and `HERMES_TUI_TOOLSETS=xcreen` applies only to that child. Bundle all runtime Python modules, not only the launcher/tools pair.

The narrow installed-host adapter reads `_sess_nowait`, `_submit_row_target_key` and `_session_db` (the same source-verified helpers as stock session history), and host dispatch metadata from `model_tools._execute_tool` / approval observability context. Native preparation uses the live runtime ID; tool dispatch's durable agent session ID is resolved back to that exact live session and requires its running flag plus a nonempty host turn ID. The exact live session object and host history revision are frozen at native preparation/context activation; a revision change rejects a first tool call too, so an ordinary no-tools completed turn cannot leak an unclaimed context to the following manual turn. This revision fence is an admission guard, not receipt authority. Missing/mismatched context fails closed, never falls back to model arguments. Receipt/reconcile intentionally do not require the old session to remain live. No context is restored automatically on restart. A fresh prepare replaces the previous automatic binding for a new batch only while the session is idle; manual prompts must revoke it explicitly, including after an automatic turn that made no tool calls.

This process-local extension requires in-process turns. The launcher explicitly refuses configured `dashboard.turn_isolation: true`, rather than silently launching a compute child without the scoped tools. It does not change that profile setting. The installed-host registration and stdio ping tests use synthetic homes, no inference, no real evidence/vault, and also exercise real `_execute_tool` turn identity plus cold receipt lookup.

## Writer durability and threat model

Effect rows reserve immutable capture day, exact source IDs and payload digest before append. A conflicting retry is rejected, not rewritten. Conventions and live sources are validated under the shared vault lock before creating a dated file; sources must still match the frozen batch timestamp/kind manifest at the write boundary. Complete markers and body digest plus retained-FD/current-path inode identity are verified before completion. Replacement marks uncertain; completed/missing or edited blocks are never blindly recreated. Saved results require all and only the batch's verified effects, with nonempty effect IDs; skipped requires `reason:"no_useful_fact"` and no effects at all. Terminal metadata is immutable and committed/read back before acknowledgment; note verification can later report uncertain without rewriting that terminal record.

Metadata lives in a UID-owned mode-0700 `HERMES_HOME/xcreen-receipts` directory. Database and sidecars must be UID-owned regular single-link private files; directory and database FDs remain open while SQLite operates, with identity checks before/after operations and commits. SQLite still opens a filename: these are fail-closed checks in a private same-user trust domain, **not** a malicious-same-UID sandbox. A same-UID process can race or rewrite files/memory; hashes are integrity checks, not authentication. No encryption/forensic-erasure claim is made. Legacy top-level writer ledgers block startup until an explicit reviewed metadata migration, never silently discarded. The bundled offline migration below handles only validated known metadata schemas. Metadata receipts have no seven-day expiry; no facts, OCR text, image URLs/pixels or credentials are stored in them.

History returns at most 20 messages / 48,000 encoded result bytes, strips structured images and data-image URLs before gateway stdout, and replaces oversized individual messages. Four immutable process-memory snapshots retain opaque cursors across concurrent first-page requests and compaction; eviction/restart returns a stale-cursor error. This method reads the host history directly and does not send/receive a full `session.history` frame first. All scoped RPC results are byte-bounded before serialization. These checks do not prove provider inference, capture/TCC behavior, or UI integration.

## Explicit legacy metadata migration

Stop xCreen first. Substitute the actual selected home and vault paths; this command is not run automatically:

```sh
python3 /Applications/xCreen.app/Contents/Resources/runtime/migrate_receipts.py \
  --hermes-home "$HERMES_HOME" --vault "/absolute/selected/vault"
# Checkout alternative: python3 runtime/migrate_receipts.py with the same flags.
```

Only entries-only five-column legacy schemas (`id,day,digest,state,position`) or seven-column metadata variants (plus `sources,batch`) are accepted, with validated bounded metadata values. The operation takes the shared vault-write lock, validates private UID-owned single-link files and integrity, reads the source read-only, writes/readbacks/fsyncs an exclusive destination, and retains the unchanged original as `*.pre-migration-backup`. It never opens note bodies, evidence or credentials, nor runs inference. Pending/uncertain states remain so; absent historic bindings become `[]` / `manual`, never invented automatic receipts. Existing destination/backup, sidecars, unknown schema or unsafe paths block with original data retained. A crash between destination publication and backup leaves an explicit conflict requiring review, never blind retry or ledger deletion. This is cooperative same-UID offline migration, not an adversarial sandbox. Other schemas need separate reviewed migration; never delete a ledger to bypass the block.

For installed-Hermes combined Swift/Python verification, set `XCREEN_HERMES_ROOT` and `XCREEN_HERMES_PYTHON` (executable from `hermes --print-runtime-command`), then `swift test`. Real registry, `_execute_tool`, scoped RPCs and gateway stdio run with synthetic home/evidence/Daily only. The test performs prepare, native manual-context revocation, verified receipt and multi-page history without `prompt.submit` or inference. The test fixture activates installed dependencies read-only with lazy installs disabled before switching to its synthetic home, avoiding a second dependency installation. Queue tests separately require every manual submit to follow its context call and reject context failure without submission.
